# State machines

Every piece of state with more than two values is a Rust enum (or one signal
holding one name), and its transitions live in one place. When adding state,
extend one of these or add a row here.

A row is state whose **order matters**: some changes are only allowed from
certain states, or a change has side effects (an email, an event, signing
devices out), or it expires. Values a user can set to anything at any time
(name, time zone, notification and newsletter choices) and config read once at startup
aren't state machines and don't get a row; their rules live in the area's
`.claude/rules/` file.

**Modeled machines** (`src/state_machines/`, test-only): a machine lists its
states and events, and `expect(state, event)` is one exhaustive `match`
returning `Moves(to)`, `Refused` (state unchanged) or `Unreachable(reason)`.
Its test (`<machine>/tests.rs`) puts a fresh row in every state, runs every
event through the real actions, and fails on any mismatch. After every
cell it also checks the machine's `rules` (side effects the state alone
doesn't show: devices, links, events, session version). `writers` lists
every function that calls a query writing the state (with its event, or
`None` for seed data); the report finds the real callers and fails `check`
when one isn't listed or a listed one is gone, so a new code path that
changes the state must be added to the model. It also writes
`target/state-machines/<machine>.json`, which `./check.sh` turns into
`target/state-machines/index.html` (`scripts/state_machine_report.py`):
every row below as a card, plus a diagram, the full state × event table and
every query that writes the state for each modeled one. The card's name must
match the `name` in the row. Modeled: Account, Role, Admin unlock, Signed in, API token, Job, Email change, Emailed link (a password reset link stands for every purpose), Account page, Form failure (the sign-in form stands for every form) Flash (guards `set_flash` / `take_flash` themselves: a `stored_in` entry ending in `@definitions` checks the functions that write, not their callers) Rate limit (the sign-in lockout for one account and IP), Permission (the Caller table by permission, plus rules on the permissions themselves), Account sections, Account event and Admin log (append-only records: a `stored_in` entry `table.*` makes any `UPDATE` of the table a writer, so editing either table fails `check` until it's modeled), Caller (an access table: each kind of caller × every `Permission` → the decision, written out by hand and checked against `caller.require` and the real API endpoints), Passkey prompt, Passkey prompt grant and Passkey reauth grant (the passkey ceremony is simulated by calling `grant_passkey_reauth` on the browser's session; the routes that use the proof are real). Two-factor, Second-factor sign-in (codes come from the real TOTP secret at the browser's moved clock) and Known device (the test browser keeps a cookie jar, so the `known_device` cookie survives sign-out and can be cleared). Subscription (signed webhooks posted to the real route; `FakeStripe` mirrors each change for the re-read), Sign-in hand-off, Authorization request and Connection (the real login, registration link and OAuth endpoints; the client row is seeded with `oauth::testing::test_client`). Browser-only state is modeled in Playwright: `e2e/tests/state-machines.spec.ts` (Form submit, Theme, Toast, Notice; Chromium only) declares the same table with `e2e/support/state-machines.ts` and writes `target/state-machines/browser/<machine>.json`, which `./check.sh` folds into the report after the Playwright step (the last two driven over HTTP through the real router by `state_machines::testing::Browser`, with the clock moved between requests; Signed in uses a second browser as the other device). A writer with no events belongs to seed data or another machine. A `stored_in` entry `session:KEY` finds session writers (`.insert(KEY` / `.remove(KEY`).

| State | Type | Transitions |
|---|---|---|
| Account | `AccountStatus` (`AwaitingPassword` → `Active`; either ⇄ `Disabled`) | `query_set_password_and_verify_user`; DB `CHECK ((password IS NULL) = (verified_at IS NULL))`; `disable_user` / `enable_user` (admin only) |
| Role | `Role` (`Subscriber` / `Admin`) | `webserver admin grant|revoke <email>` only (`change_role`; does nothing and records nothing when the role is already set) |
| Admin unlock | session `AdminUnlock { user_id, session_version, admin_since, last_used_at }` | `/admin/confirm` (`confirm_admin`) → refreshed by every admin page → expires after 15 idle minutes, a new `session_version` or a new `admin_granted_at` (role revoked and granted again) |
| Signed in | `SessionAuth { user_id, session_version, device }` in the session + a `user_devices` row | `sign_in(cx, session, user, SignInMethod)` creates the device row and a `signed_in` event; `stay_signed_in` moves this device to a new `session_version`; dropped by `load_signed_in_user` when the device row is gone or either version differs; `sign_out` / signing a device out deletes the row; `cleanup` deletes rows idle for `DEVICE_IDLE_LIMIT` or on an old version |
| Email change | `user_tokens` row (`EmailChange`, new address in `payload`) | `request_email_change` → `EmailChangeJob` (link, or a notice if the address is taken) → `confirm_email_change` switches `users.email` once / expiry |
| Emailed link | `user_tokens` row per `TokenPurpose` | `email_user_link` (replaces) → `query_consume_user_token` (once) / expiry → `cleanup` |
| Flash | `Flash` (one slot) | `set_flash` → `take_flash` on a page that accepts it |
| Toast | one `Signal<String>` per page | name or `NO_TOAST`; click / animation end → `NO_TOAST` |
| Notice | one `stage` signal | `shown` → `dismissing` → `dismissed` |
| Form submit | `submitting` signal | idle → busy on submit → idle on bfcache restore (reload) |
| Form failure | `*Problem` enums | rendered after `redisplay(…)` |
| Theme | `Theme` + cookie | `POST /theme` or `window.setTheme` (`assets/js/theme.js`) |
| Account page | `AccountTab` (`ALL`, `slug`, `path`, `pages`) + `AccountPage` (`ALL`, `slug`, `path`, `sections`) | URL → `AccountPage::from_slugs`; a section with several pages redirects to its first; unknown → 404 |
| Account sections | `AccountSection` (`anchor`, `label`, `path`) in exactly one `AccountPage::sections()` | `path()` → its page, at `#anchor` |
| Passkey prompt | `users.passkey_prompt_after` (NULL / date / `infinity`) | `answer_passkey_prompt` (`PromptAnswer::NotNow` / `Never`), only while the prompt is showing; due = no passkeys and not in the future |
| Passkey reauth grant | session `PasskeyReauth { user_id, session_version, confirmed_at }` | `finish_passkey_verification` → `take_passkey_proof` (5 min, same user and `session_version`) → `return_passkey_proof` if the action fails; `forget_passkey_proof` on passkey removal; cleared with the rest of the session when another account signs in |
| Passkey prompt grant | session `PasskeyPromptGrant { user_id, granted_at }` | `grant_passkey_prompt` (prompt shown) → `passkey_prompt_granted` (5 min) → `revoke_passkey_prompt` / `sign_in` |
| API token | `api_tokens` row (`ApiScope`s, `TokenAudience`, expiry) | create (password + email) → used (`last_used_at`) → revoked / password reset / expired → `cleanup` after 7 days |
| Caller | `Caller.via`: `Channel::Browser` / `ApiToken { id, scopes }` / `App(ConnectedApp { connection_id, scopes, label })`; `Caller.workspace`: `Workspace::Personal` | built per request (`browser_caller` / `authenticate`); checked by `authorize!(caller.require(Permission))` (role, then token scope) |
| Account event | `account_events` row (`AccountEventKind`, JSON `detail`, `EventChannel`: browser / api_token / app / admin / console / stripe, token id; an app's label in `detail.app`) | `record_event` in every account change's transaction (append-only; usage stamps and cleanup aren't events) |
| Admin log | `admin_log` row (`AdminLogAction`, admin + target public id and email as text) | `log_admin_action` in each admin action's / `webserver admin` transaction (append-only, no FKs, kept forever) |
| Job | `jobs` row (a `trait Job` type: `SendEmail` / `PasswordResetJob` / `EmailChangeJob` / `CleanupJob` / `CancelStripeSubscription` (100 attempts) / `UpdateStripeCustomerEmail`, registered in `server::job_handlers()`; `queued` / `failed`) | `enqueue` → claimed (`SKIP LOCKED`, 5-min lock, only while `attempts < max_attempts`) → deleted on success / retried with backoff / `failed` after `max_attempts`; a job whose worker died during its last attempt is marked `failed` by the next poll (`query_fail_abandoned_jobs`), never run again; one `cleanup` job reschedules itself hourly |
| Rate limit | `rate_limit_hits` rows per bucket + key | `allow_*` (insert if under the limit) / `record_*` failures / `clear_failed_logins`; rows older than a day removed by cleanup |
| Permission | `Permission` + `WorkspaceRole` (`Owner`) | checked by `Caller::require`: role grants it, then token scope if the caller is a token |
| Two-factor | `user_two_factor` row (secret, `last_used_step`) + `recovery_codes` rows (hash, `used_at`); off = no row | `enable_two_factor` (password or passkey + a code from the app; also writes 10 recovery codes) → `regenerate_recovery_codes` (replaces the codes) → `disable_two_factor` (deletes the row and codes); each app code's step and each recovery code is accepted once |
| Second-factor sign-in | session `PendingSecondFactor { user_id, session_version, started_at, method }` | a correct password (or a reset link) for a user with two-factor → `begin_second_factor` → `/login/two-factor` (`verify_second_factor`; wrong codes count against `FailedSecondFactorsByAccount`) → `sign_in` with the stored `SignInMethod`; dropped after 5 minutes, a new `session_version`, a disabled account, any other sign-in or opening `/login` |
| Known device | `known_devices` row (user, hash of the `known_device` cookie, `last_seen_at`) | every `sign_in` → touched or inserted; inserting from a password or passkey sign-in queues a "New sign-in" email unless the user opted out; `cleanup` forgets rows unseen for `KNOWN_DEVICE_LIFETIME` |
| Subscription | `subscriptions` row (`SubscriptionStatus`: `active` / `cancelling` / `past_due` / `ended`; no live row = Free) + `ends_at` when a cancellation is scheduled | only signed Stripe webhooks (`receive_stripe_event` → `apply_change`): created → Active (`subscribed`); a scheduled cancel → Cancelling (`subscription_cancelled`); `invoice.payment_failed` → Past due (`payment_failed`), `invoice.paid` → Active; a new price → same state, new plan (`plan_changed`); deleted → Ended (`subscription_ended`, terminal). Each event id is applied once (`stripe_events`) and an event older than the row's `last_event_at` is ignored; each subscription event re-reads the subscription from Stripe first and applies its current state; the customer row is locked and a partial unique index allows one live subscription per account, so a second one is cancelled and fully refunded at Stripe (`CancelStripeSubscription { refund: true }`) and recorded as `duplicate_subscription_refunded` instead of stored, once per Stripe subscription id (`duplicate_subscriptions`; a refund Stripe reports as already made counts as done); a repeated payment failure is logged once, and paying while Past due returns to Cancelling when a cancellation is scheduled |
| Sign-in hand-off | session `after_sign_in` (`Handoff::Checkout(price)` / `Handoff::Authorize(oar_…)`, 1 hour; registration carries it in the verification link's `payload`) and `checkout_pending` (1 hour) | `/login?price=` or `?authorize=` / the link's POST → `destination_after_sign_in` (taken once, before the passkey prompt: Checkout, or the approval screen) ; `/account/checkout/paid` sets pending → the Plan card polls until a subscription appears, then clears it |
| Authorization request | `oauth_requests` row (`status`: `pending` / `approved` with the code's hash, user and connection; gone = denied, exchanged or expired) | `start_authorization` → pending (`acted_at` refreshed by `keep_request_alive` while live) → `connect_app` → approved → `query_consume_code` deletes it (once) / `deny_app` deletes a pending one / 10 minutes after `acted_at` it's dead and `cleanup` deletes it |
| Connection | `oauth_connections` row (one per user and client, granted `ApiScope`s) + `oauth_tokens` rows (`access` 1 hour, `refresh` 30 idle days, `replaced_at`) | `connect_app` inserts or updates scopes (`app_connected`, email) → each refresh replaces both tokens → disconnected by `disconnect_app` / `/oauth/revoke` / reuse of a replaced refresh token (`app_disconnected`), a password reset, Sign out other devices or an admin's sign out everywhere (`disconnect_all_for_user`), or deleting the account (cascade); a disabled account's tokens are refused while it's disabled |
